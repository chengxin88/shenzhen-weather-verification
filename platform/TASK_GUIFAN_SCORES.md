## 规范口径（国家气象中心 2017 暂行版，附件7「业务评估」部分）

### 一、气温 ≤1℃ / ≤2℃ 预报准确率（1.2 节）
- ACC1 = #(|F−O| ≤ 1℃) / N，ACC2 = #(|F−O| ≤ 2℃) / N。比较时加 1e-6 容差（`abs(f-o) <= k + 1e-6`），避免 0.1 精度的浮点误差把恰好 2.0 判错。
- 「站（次）」口径：跨时次、跨站合并时按计数相加（Σ计数 / ΣN），不要先算每个时次的百分率再平均。
- 行里存计数（建议字段名 `N1`、`N2`），由前端合并后再除。
- 适用数据集：站点 2 米气温（`station_score.py`，变量 `t`）、`hk-气温-2m`（`native_archive.py` 的 `score_frame`）、`openmeteo-气温-2m`（`openmeteo_verification.py`）。
- 页面显示成百分数（例如 87.3%），越高越好（站点地图配色「越深越好」）。指标名：「≤2℃ 准确率」「≤1℃ 准确率」。说明文字写「温度预报绝对误差 ≤2℃（≤1℃）的站次百分率（规范附件7 1.2）」。
- 日最高/最低气温这次不做。

### 二、晴雨（雪）预报准确率（1.1(1) 节，表1）
- 预报有降水：F ≥ 0.1 mm。实况分三类：无降水；微量（0.0～0.1 mm）；≥0.1 mm。
- 表1 评定：
  - 实况 ≥0.1、预报有 → NA；实况 ≥0.1、预报无 → NC（漏报）
  - 实况微量、预报有 → **NA（算报对）**；实况微量、预报无 → ND
  - 实况无降水、预报有 → NB（空报）；实况无降水、预报无 → ND
- PC = (NA + ND) / N。
- 用现有 0.1 mm 阈值的 H/M/F/N，再加一个计数 `T` = #(F ≥ 0.1 且实况为微量)。这样 NA = H + T，NB = F − T，NC = M，ND = N − H − M − F，所以 PC = (N − M − F + T) / N。
- 微量的判定：
  - **站点**：观测里已有 `trace` 标志（`synop_decode.py` 的 RRR=990、`station_obs.py` 里 IEM 的 'T'）。微量 = trace 为真且值 < 0.1。
    - 请查清楚这个标志有没有进入配对数据（pairs）。没有的话要带进去，并给已有配对补上。
    - 注意 `station_obs.py` 第 284 行附近把两个时段合并时用的是 `trace and trace`。如果那里是把子时段累加成 6/12/24 小时，正确规则应是「合计 < 0.1 且任一子时段为微量」。先看清那段代码到底在做什么，再决定改不改，并在报告里说明。
  - **格点**（hk、openmeteo，实况是深圳开放数据格点分析场）：微量 = 0 < O < 0.1。
- 需要 N，所以只对有样本总数的行提供（hk、openmeteo 和站点都有 n）。
- 页面：降水页加指标「PC · 晴雨准确率」，显示成百分数。选它时阈值固定按 0.1 mm，阈值下拉框禁用或隐藏。说明写「按 ≥0.1 mm 判断有无降水，实况微量而预报有雨算报对（规范附件7 表1）」。

### 四、降水分级检验（1.1(2) 节，表2-1、表3-1）
- 量级（左闭右开）：
  - 3 小时：小雨 [0.1,3)、中雨 [3,10)、大雨 [10,20)、暴雨 [20,50)、大暴雨 [50,70)、特大暴雨 [70,∞)
  - 24 小时：小雨 [0.1,10)、中雨 [10,25)、大雨 [25,50)、暴雨 [50,100)、大暴雨 [100,250)、特大暴雨 [250,∞)
  - 低于 0.1 为第 0 级「无降水」，实况微量也算第 0 级。微量算对只用于晴雨。
- 表3-1 评定（行是实况，列是预报；每对样本最多计一次）。设 f = 预报级别，o = 实况级别：
  - f = o ≥ 1：A_o（报对）
  - f > o：B_f（空报，记在**预报**所在级）
  - f < o：C_o（漏报，记在**实况**所在级）
  - f = o = 0：不计入任何一级
- 第 k 级的指标：TS = A/(A+B+C)，POD = A/(A+C)，漏报率 = C/(A+C)，空报率 = B/(A+B)，预报偏差 = (A+B)/(A+C)。**分级不提供 ETS**。
- 适用数据集：只做 3 小时和 24 小时，规范只定义了这两种。即 `hk-降水-3`、`hk-降水-24`（含 AI 24 小时）、`openmeteo-降水-3`、`openmeteo-降水-24`、站点 `rain24`。6/12 小时不做。
- 存储建议：分级结果单独成行，带 `grade` 字段（1–6），H=A、F=B、M=C，n=N，`threshold` 为空。这样前端能复用 TS/POD/FAR/MR/BIAS 的公式，但要保证分组键里带上 grade，并且 grade 行不出 ETS。
  - 你也可以用别的干净方式，但要在报告里说清楚。
  - 数据集元数据里给出 `grades`，例如 `[{id:1,label:'小雨',range:'0.1–2.9 mm'},…]`。
- 页面：降水页加「检验方式」切换：「累加（≥阈值）」和「分级（量级）」。
  - 分级时阈值下拉框换成量级（小雨…特大暴雨）。
  - 指标只给 TS/POD/FAR/MR/BIAS。
  - 综合图（performance）在分级时也要能用；用不了就隐藏，并给出说明。
- 新疆 3 站按规范应该用表2-2「降级」档位。这次不做，在报告里列为后续。

## 兼容和迁移（重要）
1. **现有指标数值不能变。** 已有阈值的 TS/ETS/POD/FAR/MR/BIAS、ME/MAE/RMSE/CC，迁移前后必须逐位一致。
2. 缓存行：
   - 新计数需要重算。哪里有版本号或签名就要 bump，让下次刷新重算。
   - `native_archive.py` 第 440 行附近有「源数据已被清理的历史结果要保留」的逻辑。bump 后，源数据已清理、没法重算的旧行**必须原样保留**（只是没有新计数），不能因为版本变了就丢掉。openmeteo 有类似逻辑的话也一样。
3. 前端混合情况：同一数据集里有的行带新计数、有的不带。
   - 新指标只用带计数的行算，「共同有效时次」交集也只在带计数的行里求。
   - 说明区写出新指标实际覆盖的起止时间。
   - 带计数的行一行都没有时，显示「—」和原因，不能显示 0。
4. 站点配对数据是持久保存的，所以站点能从配对数据回算全部历史。
   - 写一个一次性迁移（或让下一次全量评分自动完成）：补 trace、补新计数、重建快照汇总。
   - 迁移要和现有增量评分、崩溃安全的机制兼容（见 `STATION_INCREMENTAL_REPORT.md`）。
5. 所有新缓存或改动的缓存都必须遵守现有的路径环境变量（如 `STATIONS_CACHE_DIR`，以及 native/openmeteo 现有的缓存路径变量；没有的就加，不设时等于原生产路径）。这样 Claude 才能在 Spark 上把缓存复制到预览目录，单独起一个预览服务，不碰生产。
