# 模式接入接口（2026-10-13）

测试平台入口：`/Verification/test/#interfaces`。原检验平台侧栏也有“模式接入清单”链接。
目录 API：`GET /Verification/test/api/model-interfaces`；每项的 `contract_url` 返回该产品的 JSON 协议。

按需求图片登记 14 个产品：短临 4 个、短期 7 个、台风 3 个。
ECMWF 台风复用现有 `ECMWF-IFS` 来源及 `/api/typhoon/catalog`、`/api/typhoon/score`；
其余 13 个待提供真实源资料。图片中的 `GGF-MT` 名称原样保留，实际资料命名核对后再补别名。
不同分辨率产品分别登记；短期 PANGU 和台风 PANGU 也有独立产品标识。

## 目前已经预留的内容

- 稳定产品标识、分类、接入状态、接口目录及单产品协议。
- 规则经纬度格点场 `GridRequest` / `GridAdapter.fetch_field()`。
- 台风路径 `TrackRequest` / `TrackAdapter.fetch_track()`。
- 校验模式身份、精确起报及有效时间、单位、层次、累计降水时段、网格维度和缺测值。
- HTTP 只允许读取目录、协议和适配器输出。没有上传、任意 URL 下载、凭据配置或写文件接口。

未绑定源时，合法场/路径请求返回 HTTP 503 和 `status: reserved`，不返回零场或示例评分。
绑定适配器只代表数据读取接口已配置，不代表该产品已有评分。
本次不改变现有评分模式列表，也不启用下载、回补或新增定时任务。

## 接入真实资料时

需要实际访问方式（授权 API、SFTP 或服务器本地目录等）、一份真实批次样例，
变量名/单位/缺测值/投影/覆盖范围，以及起报频率、时效间隔和最长时效。
未知能力在协议里为 `null`，不能把允许变量列表当作该模式已经支持的要素。

在可信服务器启动代码中导入具体适配器并调用 `register_adapter(product_id, adapter)`。
不从浏览器参数加载模块、文件路径或源地址；访问凭据只留在服务器。
适配器按指定的固定起报读取资料；缺失时报告不可用，不能替换为最新起报或其他模式。
同一模式多产品可以共享下载器和缓存，再按各自产品标识输出，避免重复下载。

格点场接口用 UTC ISO8601、整数分钟时效和 `[lat][lon]` 二维数组；
经纬度轴严格递增，缺测为 JSON `null`。原始投影/曲线网格应在适配器中正确转换，
保留实际覆盖和有效分辨率，不外推评分区外或源覆盖外的格点。
降水必须给出累计分钟数及累计起始时刻；当前协议不接受累计段跨越起报时刻。
台风路径须使用真实台风编号及逐点有效时间；强度风速统一输出 m/s，并注明平均时段或瞬时风口径。

数据接通后，再将其真实起报目录和标准场交给现有配对、评分、缓存流程；
在核实资料和观测时间尺度后启用对应要素。短临分钟时效不能直接套用既有 6 小时批次假设。
台风来源也须先核对真实批次及风速口径后才进入比较。
评分模块的这一步待真实样例接入时完成，本次不假定现有逐小时观测可评分任意分钟产品。

区域格点资料沿用接入目标：60–150°E、0–60°N 保留 7 天；
108–120°E、18–27°N 评分区域保留 30 天。源实际覆盖较小时仅保存其交集。
台风整条路径沿用台风归档管理，不按上述格点评分区截断。

## 验证与回滚

`python -m unittest test_model_interfaces -v` 验证协议与实际 HTTP 路由。
浏览器检查三类列表、协议下载、跳转现有台风检验和原检验入口。
部署前保存 `server.py`、`index.html`、`modules.js` 和原平台 `app.py`，
如需回滚，恢复这些文件并重启 `weather-verification-test.service`。
新建模块及文档可以保留，恢复旧入口后不会被调用。
